# 报销 OCR 整理工作流（AI 原生版）

> 这是一个**自包含的工作流 skill**：不依赖 XM报销OCR 项目代码，可整个拷走到任意机器使用。
> 核心思路——项目原本用 OCR 代码解析图片，而 AI 自身就能"看懂"截图/发票/Excel，
> 所以本 skill 让 AI 直接用视觉和工具读取文件夹，按下面定义的**统一字段契约**处理，
> 最后由参考脚本 `scripts/build_outputs.py` 机械地生成两个 Excel 并重命名源文件。

---

## 1. 适用场景

- 用户把一批报销资料（订单截图、发票 PDF、淘宝订单 Excel、报销导入模板）放进一个文件夹，说"整理一下""按流程出表""重命名这批图"。
- 用户想要：① 一份可导入报销系统的「消费明细导入 Excel」；② 一份「订单汇总 Excel」；③ 源文件按规则重命名。
- **不适用**：需要 GUI 工具、需要调用 XM报销OCR 项目代码、需要自动化定时跑。

---

## 2. 输入约定（文件夹里放什么）

AI 启动时先向用户确认**文件夹路径**。然后扫描该文件夹，识别以下四类输入：

| 类型 | 识别方式 | 说明 |
|------|----------|------|
| 订单截图 | 扩展名 `.png` / `.jpg` / `.jpeg`，且**不是**发票/模板 | 淘宝、拼多多、美团的订单支付截图 |
| 发票 PDF | 扩展名 `.pdf` | 结构化文本型发票（非扫描图片）；文件名/内容含"发票""电子发票"等 |
| 淘宝订单 Excel | 扩展名 `.xlsx` / `.xls`，且**不是**报销模板 | 淘宝后台导出的订单列表（含价格/下单时间/商品名） |
| 报销导入模板 | 扩展名 `.xlsx`，且文件名或表头含"模版/模板/导入/消费明细" | 「消费明细导入模版.xlsx」，用作报销 Excel 的骨架 |

> 若文件夹里**没有**报销导入模板，AI 按第 6 节的结构**自建一个最小合规模板**（Row1~Row4 固定结构），不必强求用户提供。

---

## 3. 处理流程（AI 执行步骤）

### Step 1 — 确认文件夹并扫描
- 拿到文件夹路径，列出其中所有文件，按第 2 节分类。
- 若无任何订单截图/发票 → 提示用户，不执行后续。

### Step 2 — 用视觉读取每张订单截图
- 对每张截图调用**视觉读取**（Read 工具，多模态）。读出以下字段：
  - `amount`（实付金额，**扣除优惠后的最终付款**，取"实付款/实付/合计/实付总额"，非商品单价）
  - `platform`（平台，按第 4 节特征词判定，必填）
  - `order_time`（订单时间，yyyy-MM-dd；**拼多多/美团**可从截图抽"下单时间/期望时间"，淘宝留空待 Step 4 从 Excel 补）
  - `product_name`（商品名；淘宝留空待 Excel 补，拼多多/美团尽量读）
- 一张图含多个订单 → `amount` 取所有"实付款"总额。
- 读不出金额或平台 → 该图 `status=failed`，记录 `reason`，**不重命名**。

### Step 3 — 读取发票 PDF
- 用 PDF 读取能力（如 PyMuPDF / 文本提取）解析结构化文本发票。
- 提取：`date`（开票日期 yyyy-MM-dd）、`amount`（价税合计）、`seller`（销售方名称）。
- 记为 `source=invoice` 的记录，平台留空（发票不判平台）。

### Step 4 — 读取淘宝 Excel 并匹配
- 用 `scripts/build_outputs.py` 里的 `load_taobao_excel` 逻辑（或 AI 直接读）解析淘宝 Excel：自动识别表头（价格/下单时间/商品名称/订单号）。
- **匹配**：用 Step 2 读出的 `amount` 在 Excel 中按价格容差（±5 元）匹配最近一行 → 补 `order_time`、`product_name`、`order_no`。
- 匹配不到（如拼多多/美团订单不在淘宝 Excel 里）→ 保留截图自读的时间/商品名，不强制匹配。

### Step 5 — 产出结构化记录（JSON）
- 把以上所有记录整理成一份 JSON（schema 见第 7 节），这是 AI 视觉读取的"成果物"，也是传给脚本的输入。
- 用户可在此时审阅/修正字段（可选）。

### Step 6 — 运行参考脚本生成输出
- 调用 `scripts/build_outputs.py`，传入记录 JSON + 配置（重命名规则 A/B、费用类型、模板路径）。
- 脚本负责：生成「报销导入 Excel」+「订单汇总 Excel」+ 按规则重命名源文件。
- 机械生成交给脚本，保证格式零误差；AI 不必手写 Excel。

### Step 7 — 输出待核对清单
- 向用户汇报：成功/失败条数、生成的文件名、未重命名的失败文件清单、需人工确认的歧义项（如价格匹配到多行）。

---

## 4. 平台判定特征词（必读，避免误判）

判平台**只看截图上的必存字段**，不用模糊词：

| 平台 | 判定特征词 | 依据 |
|------|-----------|------|
| 淘宝 | `天猫` / `淘宝` / `企`（如"企业购"） | 淘宝/天猫订单截图必存在字段，命中其一即判淘宝 |
| 美团 | `闪购` | 美团订单截图特征词 |
| 拼多多 | `拼小圈` | 拼多多订单截图特征词 |

**禁用与注意：**
- ❌ 不得用 `拼多多驿站` 判拼多多——那是代收驿站，非购物平台，会误判。
- ❌ 拼多多**不**靠直接词 `拼多多` 判定（截图常含快递/驿站名导致混淆），只用 `拼小圈`。
- 所有特征词均未命中 → `platform` 缺失 → `status=failed`（平台是必须字段）。

---

## 5. 两种重命名规则（用户选其一，默认 A）

| 规则 | 文件名格式 | 示例 |
|------|-----------|------|
| **A（默认）** | `{金额}-{平台}.{ext}` | `26.52-拼多多.png` |
| **B（带时间）** | `{时间}-{金额}-{平台}.{ext}` | `2026-03-12-26.52-拼多多.png` |

- 金额格式：整数去尾部 `.0`（如 `14`），小数保留实际位数（如 `26.52`、`26.5`）。
- 发票 PDF（两种规则均适用）：`{日期}-{金额}元-{销售方}-发票.pdf`，例：`2026-03-10-120元-某某科技-发票.pdf`。
- **失败文件（status=failed）一律不改名**，留在原地，记入待核对清单。
- **文件名冲突**：目标已存在则追加序号 `(1)`、`(2)`…。
- 仅替换文件名主体，**保留原始扩展名**，避免文件打不开。

## 6. 输出 Excel 结构（精确契约，不可破坏）

### 6.1 报销导入 Excel（消费明细导入）
以报销导入模板为骨架：复制模板 Row1(说明)/Row3(系统ID)/Row4(表头)，Row2 与 Sheet 名用费用类型覆盖，Row5+ 写数据。

| 行 | 内容 |
|----|------|
| Row1 | 说明文字（从模板原样复制） |
| Row2 | 费用类型名（= Sheet 名，默认「买耗材」） |
| Row3 | 系统内部类型 ID（从模板复制） |
| Row4 | 表头：金额 / 消费日期 / 发票形式 / 发票 / 消费事由 |
| Row5+ | 数据行 |

**字段映射（每一条成功记录）：**
- `金额` ← `amount`
- `消费日期` ← `order_time`（yyyy-MM-dd，**必填**，缺则跳过该条）
- `发票形式` ← 留空
- `发票` ← `0`（来源为截图）/ `1`（来源为发票 PDF）
- `消费事由` ← `"{月}月{日}日，{平台}购买{商品}等，共计{金额}元。"`
  - 月/日从 `order_time` 取；平台缺失退化为"购买"；商品缺失则不写"等"；金额缺失写作"元"。

> 仅导出 `status=success` 且**同时具备金额 + 消费日期**的记录（消费日期为模板必填列）。

### 6.2 订单汇总 Excel（纯数据，无模板依赖）
表头固定：**时间 / 商品名称 / 价格 / 平台 / 原文件名**
- `时间` ← `order_time`
- `商品名称` ← `product_name`
- `价格` ← `amount`
- `平台` ← `platform`
- `原文件名` ← 原始文件名

> 订单汇总包含所有记录（含失败），便于回溯。

## 7. 记录 JSON Schema（AI → 脚本 的接口）

AI 在 Step 5 产出的 JSON 结构：

```json
{
  "rename_rule": "A",
  "expense_type": "买耗材",
  "template_path": "文件夹/消费明细导入模版.xlsx",
  "records": [
    {
      "source": "screenshot",
      "original_path": "文件夹/QQ_1783556795637.png",
      "amount": 26.52,
      "platform": "拼多多",
      "order_time": "2026-03-12",
      "product_name": "一次性塑料滴管",
      "status": "success",
      "reason": ""
    },
    {
      "source": "invoice",
      "original_path": "文件夹/发票.pdf",
      "amount": 120.0,
      "seller": "某某科技有限公司",
      "order_time": "2026-03-10",
      "status": "success",
      "reason": ""
    },
    {
      "source": "screenshot",
      "original_path": "文件夹/blurry.png",
      "amount": null,
      "platform": null,
      "status": "failed",
      "reason": "截图模糊，无法识别订单信息"
    }
  ]
}
```

字段说明：
- `source`：`screenshot` 或 `invoice`。
- `status`：`success` / `failed`。失败记录不参与重命名、不进报销 Excel。
- 发票记录的 `发票` 列填 `1`；截图记录填 `0`。
- `rename_rule`：`A` 或 `B`（缺省默认 `A`）。

---

## 8. 边界情况处理

| 场景 | 处理 |
|------|------|
| 截图模糊/无法识别 | `status=failed`，不重命名，记入待核对清单 |
| 一张图含多订单 | `amount` 取实付款总额 |
| 有优惠抵扣 | 取最终实付款（扣除优惠后） |
| 价格匹配到淘宝 Excel 多行 | 取最接近一行；差距极小标"歧义"请用户确认 |
| 目标文件名已存在 | 追加 `(1)`/`(2)`… |
| 识别到金额但无平台 | `failed`（平台必填） |
| 识别到平台但无金额 | `failed`（金额必填） |
| 无报销模板 | AI 自建最小合规模板（Row1~Row4） |
| 文件夹无截图/发票 | 提示用户，不执行 |

---

## 9. 参考脚本用法

`scripts/build_outputs.py` 是纯机械实现（仅依赖 `openpyxl`），负责把第 7 节的 JSON 变成实际文件。

```bash
# 依赖（首次）
pip install openpyxl

# 运行：传入记录JSON，输出两个Excel + 重命名
python scripts/build_outputs.py --records records.json --out-dir 输出文件夹
```

脚本行为：
1. 读 `records.json`，按 `rename_rule` 重命名 `success` 的源文件。
2. 生成 `报销导入_{费用类型}_{时间戳}.xlsx`（套模板）。
3. 生成 `订单汇总_{时间戳}.xlsx`。
4. 打印成功/失败/冲突统计。

> 若你（AI）所处环境无法跑脚本，也可按第 6 节结构**直接手写两个 Excel**（用 openpyxl），并用文件操作工具重命名——脚本只是可靠性的兜底，不是唯一路径。
